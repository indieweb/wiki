== IndieWeb setup ==
* '''Hosting:''' a static [[Neocities]] site. Plain HTML and one CSS file, no JavaScript, no tracking.
* '''Sign-in:''' [[IndieLogin]] with [[rel-me]] pointing at an email address, using a <code>&lt;link rel="me" href="mailto:…"&gt;</code> in the page head. There is no GitHub or Mastodon profile tied to this site yet, so email is the simplest working option. If you try this, remember the code only works in the browser session that requested it.
* '''Next steps:''' add an [[h-card]] to the home page, mark up each note as an [[h-entry]], and publish an [[h-feed]] so the notes can be followed without a social account.

== What I'm documenting ==
=== Non-VoIP vs VoIP numbers ===
The question I get most is why a phone number "works for calls but not for sign-up codes". It almost always comes down to the line type. When you type a number into a sign-up form, the app (or the verification company behind it) runs a line type lookup against carrier and numbering databases. A number issued on a mobile network range comes back as ''mobile''; a number from an internet calling service comes back as ''VoIP''. Lookup providers also split VoIP into ''fixed'' (tied to a device, such as a broadband home phone) and ''non-fixed'' (created online with no device). Non-fixed VoIP is the type most apps refuse, because anyone can create dozens of them in minutes.

In the UK the number itself gives a lot away:
* 071–075 and 077–079 are mobile ranges, the type most forms expect.
* 070 numbers look like mobiles but are Ofcom "personal numbering" ranges that forward to another phone, and are often blocked.
* 056 is location-independent and in practice VoIP, so it is frequently refused.
* 01, 02 and 03 are landlines, and most of them can't receive SMS at all.

I wrote the full comparison, with which ranges get refused and what to use when you need a code again months later, as [https://cryptoesim.io/blog/non-voip-vs-voip-numbers non-VoIP vs VoIP number: why some apps reject your number].
